## Repository Layout

| Directory | Contents |
| --- | --- |
| `crates/` | The Rust workspace: compiler, runtime, backends, toolchain, CLI, runners, tools. |
| `foundation/` | The standard library, a real Kira package. |
| `packages/` | Kira libraries a program depends on by path, including anything platform-bound. |
| `tests-kik/` | The Kira test harnesses. |
| `examples/` | Readable programs for one part of the language each. |
| `editors/tree-sitter/` | The Kira grammar. |
| `sites/docs/` | This site. |

## Where a Change Goes

Put logic in the lowest crate that owns it, and preserve the dependency direction. [Compiler Architecture](/docs/appendix/compiler-architecture) has the layer graph.

| Change | Crates |
| --- | --- |
| Tokens | `kira-lexer`, `kira-syntax-model` |
| Grammar | `kira-parser`, `kira-syntax-model` |
| Macro expansion | `kira-macros` |
| Type checking and lowering to HIR | `kira-semantics`, `kira-semantics-model` |
| Shared IR | `kira-ir` |
| VM execution | `kira-bytecode`, `kira-vm-runtime` |
| Native lowering | `kira-llvm-backend`, `kira-native-bridge` |
| Hybrid | `kira-hybrid-runtime`, `kira-hybrid-definition` |
| Shaders | `kira-ksl-*`, `kira-shader-*`, and the five backend crates |
| Manifests and discovery | `kira-manifest`, `kira-project` |
| Commands | `kira-cli` |

## Testing

**Every Kira syntax and behavior belongs in a `tests-kik` harness.** A case is a construct-backed declaration providing `test` and `expect`, and the harness's `Test` family is Kira source rather than a compiler branch. See [Testing](/docs/foundation/testing).

| Harness | Runs |
| --- | --- |
| `tests-kik/harness` | The language surface. |
| `tests-kik/ffi-harness` | The C seam. |
| `tests-kik/syscall-harness` | System calls, on the engines that emit the instruction. |
| `tests-kik/syscall-parity-harness` | The host-servable calls, on all three engines. |

Backend-sensitive work also belongs in `crates/kira-cli/tests/backend_parity/`, which runs one program on the VM, on LLVM/native, and on hybrid and requires identical output, traps included.

```bash
cargo build --workspace
cargo clippy --workspace --all-targets -- -D warnings
kira test tests-kik/harness
```

## What Moves Together

A change that alters user-facing behavior updates three things in the same commit:

1. The harness case that proves it.
2. The page under `sites/docs/content/docs/` that documents it.
3. The `editors/tree-sitter` grammar, when the syntax moved.

Documentation for the language and the toolchain lives in `sites/docs` and nowhere else. A second markdown tree beside the code is how a manual and an implementation drift apart.
