Kira calls prebuilt C functions with no `@Native` and no glue, on every engine. [Interop and FFI](/docs/language-guide/interop-and-ffi) is the language surface; this section is the workflow around it.

## The Contract

- C ABI only. `abi: c` is the one accepted value.
- A package lists its native libraries in `package.kira` or in `NativeLibs/<name>.toml` beside it.
- Target selection is exact and structural: a host build picks the row whose triple matches this machine, and a wasm device picks the wasm row.
- Bindings may be hand-written or generated from headers by the managed `libclang`, and a generated binding is ordinary Kira source in the same dialect.
- Every backend reaches C through one generated adapter per import, so one declaration serves all of them.

## The Worked Example

`examples/ffi` is a package with one C source, one manifest, and one Kira file. The archives are not checked in; build them from `NativeLibs/ffimath.c` with the managed toolchain, then run the same program on every engine.

```bash
clang -c NativeLibs/ffimath.c -o NativeLibs/lib/ffimath.o
llvm-ar crs NativeLibs/lib/libffimath.a NativeLibs/lib/ffimath.o

kira run --backend vm main.kira
kira run --backend llvm main.kira
kira run --backend hybrid main.kira
```
