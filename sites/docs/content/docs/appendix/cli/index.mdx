`kira` is a launcher over the selected toolchain. `kira help` prints the verb list.

```text
kira run                compile and run a program on the VM
kira debug              run a program under the debugger
kira tokens             print a file's lexical tokens
kira ast                print a file's syntax tree
kira doc                render documented declarations as Markdown
kira check              analyze a program without running it
kira lint               report what a package's `linter.kira` asks about
kira test               build and run a program's tests
kira build              compile to an application or library artifact
kira ffi                inspect and bind native libraries
kira profile            record and read a sampled profile of a run
kira shader             build every KSL shader and report what each target emitted
kira new                scaffold a new project
kira sync               write `kira.lock` from the package manifests
kira add                add a dependency
kira remove             remove a dependency
kira update             update dependencies
kira package            build a library package for distribution
kira migrate-manifest   upgrade a manifest to the current format
kira live               run with live reload
kira export             generate a per-platform project (Xcode, CMake, web)
kira --version          print the version
```

`--version` is a flag rather than a verb, because that is the spelling every tool teaches a caller's fingers.

## The Path Argument

`run`, `build`, `check`, `test`, `debug`, `lint`, `doc`, `sync`, and `update` all take an optional `[file|dir]`. Omitting it means the package directory you are standing in. A directory holding no `package.kira` is refused by name rather than searched upward from.

Everything after `--` goes to the program rather than to `kira`.

## Provisioning Is knvm's Job

`kira` does not fetch its own engines. `knvm install-llvm` and `knvm install libffi` do, because `knvm` is what owns every managed install, and because a `kira` that could fetch LLVM would be a binary that had to exist before the thing it installs. See [Toolchains](/docs/appendix/toolchains).

## The Checkout You Are Editing

Install it as the `dev` toolchain and keep typing `kira`:

```bash
knvm binstall
```

Or run one command without selecting anything:

```bash
cargo run -p kira-cli --bin kira -- run examples/hello
```

## Diagnostics

A failing command renders Kira-native diagnostics with a code, a title, the source location and caret, and any help or notes. Invalid Kira fails as Kira, at the pass that found it, rather than as an internal panic or a raw linker message. See [Diagnostics](/docs/appendix/diagnostics).
