Every refusal Kira makes carries a code, and the code is the stable part. A message may be reworded; `KSEM107` will always be a use after move.

## Prefixes

| Prefix | Owner |
| --- | --- |
| `KLEX` | The lexer. |
| `KPAR` | The parser. |
| `KMAC` | Macro expansion. See [Macro Diagnostics](/docs/macros/diagnostics). |
| `KSEM` | Semantic analysis. The largest set by far. |
| `KIR` | HIR and IR lowering. |
| `KBE` | A code-generation backend. |
| `KSLP`, `KSLS` | The KSL parser and KSL semantics. |
| `KPK` | Package and project discovery, and manifests. |
| `KTC` | Toolchain discovery and activation. |
| `KCL` | The command line. |
| `KLINT` | The package's own linter. |
| `KIC` | An internal compiler error. |

A diagnostic also carries a domain tag naming the subsystem it belongs to: `cli`, `package`, `toolchain`, `backend`, `lowering`, or `compiler_internal`.

## What a Rendered Diagnostic Carries

- Severity.
- The code.
- A title and a message.
- The source location, with a caret under the span.
- Related labels pointing at other spans, when a second location explains the first.
- Help, a suggestion, and notes, when there is a concrete next move.

```text
error[KPAR001]: expected expression
  --> app/main.kira:12:19
```

`--show-notes` opts into the note-level output that a normal run keeps quiet.

## Invalid Kira Fails as Kira

Parser failures are Kira parser diagnostics, semantic failures are Kira semantic diagnostics, and backend and build failures are Kira build diagnostics. An unexpected internal failure goes through an internal compiler error boundary rather than surfacing as a panic, a raw linker message, or a host runtime crash.

The bar for a diagnostic is not "emit an error". It is "emit a Kira-native error at the pass that found it, with stable and useful output".

## Codes Worth Knowing

These are the ones that come up most often while learning the language. Each is explained where the rule lives.

| Code | Means |
| --- | --- |
| `KLEX003` | An unknown escape in a string literal. |
| `KPAR043` | `@Export` on a `struct`, pointing at the `class` that would work. |
| `KPAR047` | A generic `struct`, `class`, or `function`. Only `enum` takes type parameters. |
| `KPAR075` | A bare `self` receiver. |
| `KPAR077` / `KPAR078` | A construct parameter list with no `extends`, or a declaration naming two families. |
| `KSEM003` | A duplicate declaration. |
| `KSEM011` / `KSEM255` | No `@Main` in an application, or one in a library. |
| `KSEM027` / `KSEM032` | A namespace root this file did not import, or an import naming no readable file. |
| `KSEM052` | A by-value struct cycle. |
| `KSEM062` | A missing argument for a parameter with no default. |
| `KSEM063` | A derived class assigned to an ancestor binding. There is no subtyping. |
| `KSEM071` | Two different written widths in one operation. |
| `KSEM081` | `print` of a struct, array, or enum. |
| `KSEM107` | A use after move. |
| `KSEM113` / `KSEM115` | A named non-trivial value passed to a copying parameter with no spelling, or `move` where the parameter copies. |
| `KSEM117` | A closure capture that owns heap storage. |
| `KSEM118` / `KSEM119` | An enum payload the box cannot own, or a leading-dot variant with no expected type. |
| `KSEM125`, `KSEM127`, `KSEM129` | A `match` subject that is not an enum, a variant matched twice, a variant not covered. |
| `KSEM137`–`KSEM143` | The `attempt` / `try` / `handle` rules. |
| `KSEM157` / `KSEM130` | A cyclic type alias, or an alias claiming a taken name. |
| `KSEM158` / `KSEM159` | An unknown task-handle operation, or a task body outside the allowed shape. |
| `KSEM160`–`KSEM168` | The `@Export` boundary rules. |
| `KSEM172`–`KSEM175` | The generic-enum rules. |
| `KSEM200`–`KSEM207` | The construct-family rules. |
| `KSEM234` | A backed declaration leaving a requirement unimplemented. |
| `KSEM240` / `KSEM213` | Parameter defaults or field defaults that fill each other without end. |
| `KSEM247` / `KSEM248` | Two mutable borrows of one binding in a call, or a `borrow mut` of a temporary. |
| `KSEM279`–`KSEM284` | The `@FFI.Syscall` rules. |
| `KSEM288`–`KSEM298` | The trait rules. |
| `KSEM300`–`KSEM307` | The `Drop` rules. |
| `KSEM308`–`KSEM312` | Supertraits, `Send`, `Sync`, and the task boundary. |
| `KIR005` | `@Derive(Copy)` on a type that moves. |
| `KPK025` | A `*_types.kira` file outside `bind-types/`. |
| `KPK041` | A generated binding adopted as package source because it carries no stamp. |
