Kira Live is a **networked server/client system**. `kira live` builds your program into a `.klbundle`, serves it over TCP, and connects a runner that downloads it, hosts it, and takes new bundles as you save. The **desktop runner is complete**; macOS and the iOS simulator run the same protocol inside an exported Xcode app; the Web serves a page; Windows, Linux, and Android are audited honestly where no loop exists yet.

```bash
kira live                          # this package, on the desktop runner
kira live desktop app.kira         # same runner, named
kira live macos                    # exported Xcode app, launched live
kira live ios                      # iOS simulator via the exported workspace
kira live ios-device               # refused with its provisioning prerequisite
kira live web                      # build + serve exports/web, open a browser
```

Useful flags: `--watch`/`--no-watch` (watching is automatic at a terminal), `--backend vm|llvm|hybrid` for the bundle's engines, and `--quit-after 5s` to bound a session without bypassing the handshake.

## Flow

```text
kira live <runner> <target?>
  -> compile the program into a .klbundle
  -> start the live server (127.0.0.1, OS-assigned port)
  -> bring up the runner, pointed at that address
  -> runner connects, downloads the bundle
  -> runner loads, links, and starts the entrypoint
  -> source change rebuilds a fresh bundle
  -> hot patch when safe, relaunch when not
```

## The runners

- **Desktop** spawns `kira-desktop-runner` beside the compiler: VM bytecode, whole-program native libraries, and hybrid sessions all host in one process.
- **macOS / iOS / tvOS / visionOS** generate the real Xcode workspace (`exports/apple/`) with `mode = "live"` and this session's port baked into the app's manifest, run `xcodebuild` against the platform SDK or an available simulator, launch the built app, and accept its connection. A reload that changes the embedded native half relaunches through an incremental `xcodebuild` first — restarting a binary whose linked code changed would silently run stale code.
- **Web** compiles exactly as `kira export web`, serves `exports/web` from a traversal-proof static server with the correct wasm content type, and opens the page. While watching, every save recompiles and swaps the served module; the page picks it up on its next reload — Kira does not inject a livereload socket into your page.
- **Windows / Linux** write their CMake scaffolds, audit the tools a local build needs (`cmake`, `ninja`; Visual Studio only exists on Windows hosts), and say precisely which part of the loop this host cannot provide.
- **Android** has no runner client in this build yet and refuses by name.

## The `.klbundle` boundary

The `.klbundle` directory is the **runner artifact boundary**. Runners consume bundle manifests, bytecode/hybrid payloads, foreign-binding manifests, and staged dependencies — they never reach into compiler internals. Reload tiers are decided by comparing manifests: identical is nothing to do; VM-only sessions can swap bytecode at a frame boundary; anything else relaunches, loudly, rather than crossing an unproven ABI.

## Observable events

A live session emits a precise event sequence, which is what tests assert against rather than relying on "a window opened":

```text
live.server.started        live.bundle.built          live.client.connected
live.bundle.requested      live.bundle.sent           live.bundle.received
live.bundle.loaded         live.bundle.linked         live.entrypoint.started
live.frame.presented       live.session.ready         live.watch.started
live.source.changed        live.bundle.rebuilt        live.reload.notified
live.reload.staged         live.reload.applied        live.reload.completed
live.reload.rejected       live.app.exited            live.runner.relaunched
live.shutdown.started      live.shutdown.finished
```

## Physical devices

A device target costs signing and provisioning that no toolchain can automate from here: attach the device, open the generated Xcode project once, and let Xcode trust it. `kira live ios-device` says exactly that instead of pretending a simulator run proved a phone.
