Kira models runners with **typed ids**, not ad-hoc strings. Every id parses, because a command that fails to parse cannot explain itself. A runner this build cannot drive gets a precise diagnostic naming what is missing rather than failing as an unknown command.

## Runner Ids

```text
desktop  macos  ios  tvos  visionos  windows  android  web  linux
```

`ios-simulator` and `ios-device` are spellings of `ios` that select which physical kind an Apple run targets.

| Platform | Default runner |
| --- | --- |
| Desktop | `kira` |
| Apple (macOS, iOS, tvOS, visionOS) | `xcode` |
| Windows | `visual-studio` |
| Android | `android-studio` |
| Web | `kira-wasm` |
| Linux | `cmake` |

## Build Profiles

| Profile | Backend | Optimization | For |
| --- | --- | --- | --- |
| `debug` | vm | none, with debug symbols | Iteration. |
| `profiler` | llvm | light, with debug symbols and profiling | A recording that still names its frames. |
| `release` | llvm | full, stripped, LTO | Shipping. |

`profiles.profiler` is the supported profiling profile; `profiles.profile` is reserved so configs do not silently drift between the noun and the mode name. The profile index is a wire format: a `.klbundle` records its profile as that index.

## Runner or Path

`kira live ios` means runner `ios` and the current project. `kira live ./ios` means the default runner with target path `./ios`.

The distinction is made on **shape, not on what happens to exist**: a path-looking argument stays a path even when nothing is there, so the error says the file is missing rather than that the runner is unknown. A runner id is recognized only in the first positional slot.

## The Honesty Rule

A runner is a host bridge, not the app. It may create windows, surfaces, canvases, devices, event loops, and logging bridges, but it must not draw content of its own and call it Kira output.

Host-only evidence is reported with `HOST_*` markers and never satisfies Kira runtime, UI, layout, graphics-frame, or visible-content success. Apple, Android, and iOS live reporting keep build, device detection, install, launch, and protocol states separate, and emulator-only or simulator-only success is never reported as physical-device success.
