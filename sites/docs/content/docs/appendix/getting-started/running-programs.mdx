## The Everyday Commands

```bash
kira run          # compile and run, on the VM by default
kira check        # analyze without running
kira test         # build and run the package's tests
kira build        # compile to an artifact
kira lint         # report what the package's linter.kira asks about
kira doc          # render documented declarations as Markdown
```

Every one of them takes an optional `[file|dir]`. Omitting it means the package directory you are standing in, so `kira check` inside an app is `kira check .`. A directory holding no `package.kira` is refused by name.

A bare `.kira` file with no manifest above it is a program, which is why one handed to the compiler still reports a missing `@Main`.

## Choosing a Backend

```bash
kira run --backend vm app.kira        # interpreted bytecode
kira run --backend llvm app.kira      # machine code
kira run --backend hybrid app.kira    # both, in one process
kira build --device wasm32 app.kira   # a wasm32-emscripten module
kira run --backend llvm --sanitize address app.kira
```

The VM is the default because it needs no linker. `--backend llvm` and `--backend hybrid` both need the managed LLVM. See [Execution Model](/docs/language-guide/execution-model).

`--sanitize address` instruments native memory access. It covers the whole LLVM backend and the `@Native` half of a hybrid program. Hybrid runs start a child with the managed AddressSanitizer runtime loaded before the native library. VM and Web builds refuse the flag.

AddressSanitizer runtimes come only from Kira's managed LLVM bundle. A bundle without compiler-rt fails with the expected path instead of using Xcode, Command Line Tools, or another host compiler.

## Where Artifacts Land

Everything goes under `.kira-build/`.

| Command | Primary output |
| --- | --- |
| `build` | `.kira-build/<name>.kbc` |
| `build --backend llvm` | a host executable |
| `build --backend hybrid` | `<name>`, `<name>.khm`, `<name>.kbc`, and the native half |
| `build` in a library package | the artifact plus a generated Rust crate under `.kira-build/rust/` |
| `build --target <triple>` | `.kira-build/<toolchain-triple>/`, so a cross build never overwrites a host one |

## Passing Arguments

Everything after `--` goes to the program rather than to `kira`.

```bash
kira run app.kira -- --verbose input.txt
```

## Inspecting the Frontend

```bash
kira tokens app.kira    # the lexical tokens
kira ast app.kira       # the syntax tree
kira ffi                # inspect and bind native libraries
```

Use them when a parse failure is not obvious from the diagnostic.

## Running the Checkout You Are Editing

Install the checkout as the `dev` toolchain once, and keep typing `kira`:

```bash
knvm binstall
```

To run one command without selecting anything:

```bash
cargo run -p kira-cli --bin kira -- run examples/hello
```
