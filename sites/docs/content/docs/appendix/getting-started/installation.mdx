## Install The Tools

One command puts `knvm` and the `kira` launcher on your `PATH`:

```bash
curl -fsSL https://kira-lang.com/install.sh | sh
```

On Windows, in PowerShell:

```powershell
irm https://kira-lang.com/install.ps1 | iex
```

The bootstrap installs the *tools*, not a compiler: `knvm` is the version
manager, and `kira` is a launcher that runs whichever toolchain is selected.
Open a new terminal, then install a toolchain:

```bash
knvm install latest
kira --version
```

`knvm install <version>` also accepts `--channel dev`, which installs from the
prereleases published between weekly versions.

If you would rather not run a script from a pipe, download the
`knvm-<version>-<host-key>.tar.gz` archive from
[GitHub Releases](https://github.com/kira-lang-com/kira/releases), verify it
against the `.sha256` published beside it, unpack it, and put its `bin/`
directory on your `PATH`. From there `knvm install latest` provisions
everything else.

## Provision The Managed Toolchains

Two engines are fetched rather than built, and both are pinned by this
repository:

```bash
knvm install-llvm
knvm install libffi
```

- **LLVM** backs native builds and the native half of hybrid mode. It is
  discovered at `KIRA_LLVM_HOME`, then at
  `~/.kira/toolchains/llvm/<llvm-version>/<host-key>/`.
- **libffi** backs foreign calls. Kira links it statically, so the archive for
  the machine being *built for* has to be installed — `knvm install libffi`
  installs every published target, so cross builds work from any host. It is
  discovered at `KIRA_LIBFFI_HOME`, then at
  `~/.kira/toolchains/libffi/<libffi-version>/<target>/`.

### Rate Limits

Both fetch from GitHub, which allows sixty unauthenticated API requests an hour
per address — shared, so an office network or a CI runner can exhaust it on
somebody else's traffic. `knvm` and the bootstrap scripts send `GH_TOKEN` or
`GITHUB_TOKEN` when either is set, which raises the limit:

```bash
export GH_TOKEN="$(gh auth token)"
```

The token is sent to GitHub's own hosts and nowhere else.

## Verify The Install

```bash
kira check path/to/main.kira
kira run path/to/main.kira
kira build path/to/main.kira
```

Those three are the minimum "is my install healthy?" check:

- `check` validates the program
- `run` executes it on the VM
- `build` proves the native backend and its managed LLVM are usable

## Install From A Checkout

Contributors build the tools from the monorepo with cargo, and land them the
same way the bootstrap does:

```bash
cargo run -p kira-knvm -- sinstall
```

That installs `knvm`, `kira`, and `kira-language-server` into `<kira-home>/bin`
and configures your shell to find them. To make the checkout itself the
selected toolchain:

```bash
knvm binstall
```

`binstall` builds the enclosing checkout optimized — `--debug` for the
unoptimized build — and selects it on the `dev` channel, so `kira` runs what
you just compiled. Re-running it always replaces the tree.

`kira new` scaffolds a `kira.toml` and `app/main.kira` starter app.
