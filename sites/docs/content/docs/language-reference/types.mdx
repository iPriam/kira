## Builtin Types

| Group | Names |
| --- | --- |
| General | `Void`, `Int`, `Float`, `Bool`, `String` |
| Fixed-width integers | `I8`, `I16`, `I32`, `U8`, `U16`, `U32`, `U64` |
| Fixed-width float | `F32` |
| Top type | `Any` |
| Interop | `RawPtr`, `CString` |

There is no `I64` and no `F64`: `Int` is the 64-bit signed integer and `Float` the 64-bit float. `Int32` is accepted as an alias for `I32`. There is no `I128`, no `U128`, and no `Char`.

Every integer type is one 64-bit two's-complement value at run time and every float type one 64-bit IEEE-754 value. A fixed-width name decides type distinctness and the signedness of `/`, `%`, and the four orderings, and nothing else. See [Basic Operators](/docs/language-guide/basic-operators#fixed-width-scalars).

## Assignability

Two written widths must match exactly. Bare `Int` and `Float` are wildcards matching any width in their kind, which makes assignability non-transitive: `U8` to `Int` and `Int` to `U32` both hold while `U8` to `U32` does not.

`Any` accepts every type. A generic instantiation reaches another instantiation of the same template when each type argument stays as it was or becomes `Any`. A position that merely contains one does not widen: `[Result<Int, E>]` is not `[Result<Any, E>]`.

There is no subtyping between classes (`KSEM063`), no implicit numeric widening, and no truthiness.

## Arrays

`[T]` for any `T`, nested to any depth. An array is a shared handle that moves on binding and detaches on write. Its surface is `.append(v)`, `.count`, and `xs[i]`.

## Function Types

```kira
(Int) -> Int
(Float, RawPtr) -> Void
() -> Int
```

A function type is written after `:` on a declaration that returns one, because `->` would be ambiguous with the function type's own arrow.

A function type is `Send` and `Sync` for neither: its values are closures, and a closure may have captured a `var`.

## Named Types

`struct`, `class`, and `enum` each declare a type by name. A `class` is a struct that inherits and flattens; its static type is always its dynamic type. A parameterized aggregate or enum declares one nominal row for each concrete argument list.

Enums, structs, classes, traits, and functions may take type parameters.
`Result<Int, AppError>` and `Box<Int>` name concrete rows; a bare generic enum
names none (`KSEM172`). Generic functions infer from value arguments or accept
explicit type arguments. An arity mismatch is `KSEM174`, type arguments on a
non-generic type are `KSEM173`, and a template that grows its own argument
without end is `KSEM175`.

## Trait Existentials

A trait's name in a type position holds a value of some conforming type, dispatched dynamically.

```kira
let one: Scored = Key(n: 3)
let both: [Scored] = [Key(n: 2), Token(n: 30)]
```

The four compiler-known traits, `Copyable`, `Drop`, `Send`, and `Sync`, are refused there (`KSEM295`): they state facts about one type's own members and classify no values.

## Family Types

A construct family's bare name is not a type (`KSEM207`). `Any Family` and `some Family` both name a value of some declaration backing it, and they resolve to the same type.

## Type Aliases

`type Name = Target` is a spelling, not a new type. Analysis resolves it away, so no backend learns the alias existed. A cyclic chain is `KSEM157`, and claiming a name that already means something is `KSEM130`.

## FFI Type Forms

Each is a `struct` carrying an annotation, and each names a C shape rather than a Kira value shape.

| Declared | Names |
| --- | --- |
| `@FFI.Struct { layout: c; }` | A struct laid out as C lays out its declaration. |
| `@FFI.Pointer { target: T; ownership: borrowed; }` | A typed pointer. Members of a C-layout target are read through it. |
| `@FFI.Array { element: T; count: N; }` | An inline C array. Its elements live in one field named `elements`. |
| `@FFI.Callback { abi: c; params: […]; result: T; }` | A C function-pointer type. |
| `@FFI.Alias` | A generated binding's transparent alias for a C typedef. |

`CString` is illegal in an ordinary Kira local or parameter. It is a foreign parameter, a foreign result, or a member of a C-layout struct.
