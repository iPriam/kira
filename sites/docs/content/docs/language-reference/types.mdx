## Builtin Types

| Group | Names |
| --- | --- |
| General | `Void`, `Int`, `Float`, `Bool`, `String` |
| Fixed-width integers | `I8`, `I16`, `I32`, `U8`, `U16`, `U32`, `U64` |
| Fixed-width float | `F32` |
| Top type | `Any` |
| Interop | `RawPtr`, `CString` |

There is no `I64` and no `F64`: `Int` is the 64-bit signed integer and `Float` the 64-bit float. `Int32` is accepted as an alias for `I32`. There is no `I128`, no `U128`, and no `Char`.

Every integer type is one 64-bit two's-complement value at run time and every float type one 64-bit IEEE-754 value. A fixed-width name decides type distinctness and the signedness of `/`, `%`, and the four orderings, and nothing else. See [Basic Operators](/docs/language-guide/basic-operators#fixed-width-scalars).

## Assignability

Two written widths must match exactly. Bare `Int` and `Float` are wildcards matching any width in their kind, which makes assignability non-transitive: `U8` to `Int` and `Int` to `U32` both hold while `U8` to `U32` does not.

`Any` accepts every value. What it holds is asked with `value is Type` (a `Bool`, by nominal runtime identity: two packages' same-named `Point`s are different answers) and read back with `value as Type`, which traps when the value holds anything else.

A failed cast traps, and `try value as Type` inside an `attempt` makes it an answerable failure instead: see [statements](/docs/language-reference/statements).

`value.type` answers with a `Type`, the runtime descriptor of what the value is. Two descriptors are equal exactly when they name one type by package-qualified nominal identity. A descriptor exposes five things and no more:

| Member | Answers |
| --- | --- |
| `name` | The declared name, as written. |
| `package` | The declaring package's identity, empty for a builtin and for the program's own declarations. |
| `kind` | `struct`, `class`, `enum`, `distinct`, `array`, `int`, `float`, `bool`, `string`, `pointer`, `construct family`, `trait existential`, `function type`, or `type`. |
| `arguments` | `[Type]`, the generic arguments an instantiation was minted with. |
| `conformances` | `[String]`, the traits the type keeps, sorted. |

Fields, layout, methods, and source spans are compile-time facts and are reached through comptime reflection, not through a runtime descriptor. Asking a descriptor for anything else is `KSEM363`, and asking `.type` of an expression that names no value is `KSEM362`.

Integer spellings share one descriptor, as they share one erased identity: `(3).type == (3 as U8).type`. A `distinct` keeps its own, even though a backend stores its representation. One generic specialization never reaches another: `Result<Int, E>` does not fill a `Result<Any, E>` position, and neither does `[Result<Int, E>]` fill a `[Result<Any, E>]` one. The conversion is written, by unpacking the value and rebuilding it.

There is no subtyping between classes (`KSEM063`), no implicit numeric widening, and no truthiness.

## Arrays

`[T]` for any `T`, nested to any depth. An array is a shared handle that moves on binding and detaches on write.

Its surface is `.append(v)`, `.count`, `xs[i]`, `.contains(v)`, `.rev()`, and `.sort_by(compare)`.

- `contains` performs a linear scan and requires `element == value` to be defined.
- `rev()` returns a reversed array value. `for x in xs.rev()` is recognized as reverse iteration and walks the original array without first building the reversed copy.
- `sort_by` returns a sorted copy. Its comparator has the shape `(borrow T, borrow T) -> Bool` and returns `true` when the first value belongs before the second.

## Tuples

Tuple values and tuple types have two through four elements.

```kira
let pair: (Int, String) = (7, "seven")
let point = (10, 20, 30)
print(pair.0)
print(pair.1)
```

A tuple is an ordinary value aggregate after analysis. Its elements are read with `.0`, `.1`, `.2`, and `.3`, and a tuple may be returned from a function like any other value:

```kira
function split() -> (Int, String) {
    return (42, "answer")
}
```

Parentheses around one value or one type remain grouping, so `(value)` and `(Int)` are not one-element tuples.

## Iterators

`Iterator<T>` is Foundation's lazy pull iterator. It stores one `next: () -> Option<T>` closure. A `for value in iterator` loop repeatedly calls that closure until it returns `.None`; `.Some(value)` becomes the loop binding. The iterator expression is evaluated once, and `continue` pulls the next value normally.

Iterator state belongs to whatever the `next` closure captures, so a custom iterator can walk a tree, stream values, or generate values without materializing an intermediate array.

## Function Types

```kira
(Int) -> Int
(Float, RawPtr) -> Void
() -> Int
```

A function type is written after `:` on a declaration that returns one, because `->` would be ambiguous with the function type's own arrow.

A function type is `Send` and `Sync` for neither: its values are closures, and a closure may have captured a `var`.

## Named Types

`struct`, `class`, and `enum` each declare a type by name. A `class` is a struct that inherits and flattens; its static type is always its dynamic type. A parameterized aggregate or enum declares one nominal row for each concrete argument list.

### Nominal identity

A declared type is identified by where it was declared, not by how it is spelled: the resolved package (its name, version, and dependency instance), the module inside that package, the declaration's name, and, for an instantiated generic, the identity of every argument. Two packages may each declare a `Point`, and the two are different types everywhere identity is asked: a `Point` from one never fills a parameter typed with the other's, `Box<Point>` instantiated over each is a separate row, and an `Any` holding one never compares equal to an `Any` holding the other. Aliases are transparent, so `type Byte = U8` names `U8` itself; a `distinct` stays its own type even when its representation is the same scalar. The same identity is what native-state fingerprints, generated symbols, and serialized type names are built from, so nothing downstream falls back to a bare name.

Enums, structs, classes, traits, and functions may take type parameters.
`Result<Int, AppError>` and `Box<Int>` name concrete rows; a bare generic enum
names none (`KSEM172`). Generic functions infer from value arguments or accept
explicit type arguments. An arity mismatch is `KSEM174`, type arguments on a
non-generic type are `KSEM173`, and a template that grows its own argument
without end is `KSEM175`.

## Trait Existentials

A trait's name in a type position holds a value of some conforming type, dispatched dynamically.

```kira
let one: Scored = Key(n: 3)
let both: [Scored] = [Key(n: 2), Token(n: 30)]
```

The five compiler-known traits, `Copyable`, `Drop`, `Send`, `Sync`, and `Equatable`, are refused there (`KSEM295`): they state facts about one type's own shape and classify no values. `Equatable` names the structural-equality fact `==` reads — a type conforms when its every leaf is comparable — so it may bound a type parameter (`<T: Equatable>`) but, like the others, is derived rather than declared and cannot be written as an `extend` block.

## Family Types

A construct family's bare name is not a type (`KSEM207`). `Any Family` and `some Family` both name a value of some declaration backing it, and they resolve to the same type.

## Type Aliases

`type Name = Target` is a spelling, not a new type. Analysis resolves it away, so no backend learns the alias existed. A cyclic chain is `KSEM157`, and claiming a name that already means something is `KSEM130`.

## Distinct Types

`distinct Name = Representation` is a new type over one scalar word. It is the opposite of an alias: a value crosses in only through `Name(value)` and out only through `.raw`.

```kira
distinct TabId = U32
distinct BookmarkId = U32

let id = TabId(U32(1))
let word: U32 = id.raw
```

`TabId` is assignable to `TabId` and to nothing else. Its representation does not reach it, it does not reach its representation, and a second declaration over the same representation is a third type. Assigning across any of those is the ordinary mismatch, `KSEM020` in a binding and `KSEM063` at a call.

The representation is an integer width, a float width, `Bool`, `RawPtr`, or another distinct type; anything else is `KSEM345`. A chain flattens to the scalar at its end, so `.raw` reads that scalar in one step whatever the chain's length. A cyclic chain is `KSEM346`, and claiming a name that already means something is `KSEM130`.

The type is **transparent**: it has the size, the alignment, and the ABI of its representation, with no wrapper value and no allocation. Lowering rewrites every distinct type to its representation before any backend sees a program, so the two crossings compile to no instruction at all.

Its operator surface is its representation's. Arithmetic, bitwise, and shift operators between two values of the same distinct type — or one and a bare literal — yield the distinct type again; the comparisons and equality yield `Bool`; and a distinct type over an integer indexes an array. A bare `Int`/`Float` literal adapts into it exactly as it adapts into a written integer width. The nominal boundary is what stays refused (`KSEM071`): two *different* distinct types share no operator, and a distinct type does not combine with a *written* representation value — only a bare literal pairs. `print` is refused too, so a distinct type is rendered through `@Derive(Serializable)` or `.raw`. Reading anything but `raw` off one is `KSEM349`, and constructing one from the wrong type is `KSEM348`.

At an `@FFI.Extern` signature a distinct type crosses as its representation, so the C prototype is the scalar's. The Kira side stays nominal: a parameter written `TabId` takes a `TabId` and refuses the `U32` underneath it (`KSEM183`).

Foundation's `@Derive(Equatable)`, `Clone`, `Hashable`, `Serializable`, and `Ordered` all apply. Each delegates to the representation, so the wire form of a distinct type over `U32` is `Port(U32(8080))`. `@Derive(Tagged)` does not apply: it answers which number a *variant* is, and a distinct type has none. `@Derive(Copy)` is refused (`KPAR086`): the type is one scalar word, so it is copyable already.

## FFI Type Forms

Each is a `struct` carrying an annotation, and each names a C shape rather than a Kira value shape.

| Declared | Names |
| --- | --- |
| `@FFI.Struct { layout: c; }` | A struct laid out as C lays out its declaration. |
| `@FFI.Pointer { target: T; ownership: borrowed; }` | A typed pointer. Members of a C-layout target are read through it. |
| `@FFI.Array { element: T; count: N; }` | An inline C array. Its elements live in one field named `elements`. |
| `@FFI.Callback { abi: c; params: […]; result: T; }` | A C function-pointer type. |
| `@FFI.Alias` | A generated binding's transparent alias for a C typedef. |

`CString` is illegal in an ordinary Kira local or parameter. It is a foreign parameter, a foreign result, or a member of a C-layout struct.
