title: Lexical Structure
description: Comments, identifiers, keywords and contextual identifiers, punctuation, literals, string escapes, and statement terminators.
---

## Comments

```kira
// a line comment
/// a documentation comment
```

Consecutive `///` lines immediately above a declaration are its documentation. The lexer treats every comment as trivia, so a comment never reaches the parser.

## Identifiers

An identifier begins with a letter or `_` and continues with letters, digits, or `_`. A qualified name is dot-separated: `Geo.Point`, `FFI.Pointer`, `bindings.callbacks`.

## Keywords

These are reserved and cannot be used as names:

```text
function  let     var       return    if      else    while
true      false   import    as        struct  enum    class
construct trait   extends   override  match   attempt try
for       in      break     continue  type
```

`handle` is deliberately absent: it is recognized contextually after an `attempt` block and stays usable as a name everywhere else.

## Contextual Identifiers

These carry meaning in one position and remain ordinary names everywhere else, so a local named `move` still binds:

```text
move  copy  borrow  mut  some  Any  async  extend  macro  comptime
init  requires  lifecycle  self  For
```

`extend` is recognized only when the next tokens are an identifier followed by `{` or `:`. `For` is recognized only as the first token of a content-block item, followed by `(`.

## Punctuation and Operators

```text
@  (  )  {  }  [  ]  ;  ,  :  .  ..  =  ->  ?
!  ~  +  -  *  /  %  <<  >>  &  |  ^
==  !=  <  <=  >  >=  &&  ||
```

`..` appears only in a `for` header. `#` is not a token of the language: `#{ … }` is read out of the raw source inside a macro `quote`, and a `#` anywhere else is an unknown character.

## Literals

Integer, float, string, and boolean. There is no character literal.

A string literal resolves seven escapes:

| Escape | Produces |
| --- | --- |
| `\n` | newline |
| `\t` | tab |
| `\r` | carriage return |
| `\e` | escape |
| `\0` | NUL |
| `\"` | a quote |
| `\\` | a backslash |
| `\` before a newline | nothing: the literal continues on the next line |

A backslash before anything else is `KLEX003` rather than the character itself.

## Terminators

A statement ends at a newline or at a `;`. Both are accepted everywhere, and enum variants are separated by newlines or spaces rather than commas. Array and argument list commas are optional where a newline separates the elements.
