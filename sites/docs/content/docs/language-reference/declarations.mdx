## Top-Level Forms

```text
import  function  let  struct  class  enum  trait  construct  extend  type  distinct
macro   comptime macro    comptime function
```

## `import`

```kira
import geometry
import geometry as Geo
import shapes.Rect as Rect
import Foundation
```

A module name is a name, not a path. One segment is a sibling file; a dot is a directory separator. Imports are file-scoped, and an import naming no readable file is `KSEM032`. Referring to a namespace root this file did not import is `KSEM027`.

## `function`

```kira
function name(param: T, other: U = default) -> R { … }
function name(param: T): (Int) -> Int { … }         // a function-typed result
function method(borrow self) -> R { … }
function method(borrow mut self, by: Int) { … }
function identity<Value>(value: Value) -> Value { … }
@FFI.Extern { … } function foreign(a: I32) -> I32 // bodyless
```

Parameters require explicit types. A parameter mode is `borrow`, `borrow mut`, `copy`, or nothing. A result type follows `->`, or `:` when it is itself a function type. A bare `self` receiver is `KPAR075`; a receiver on a non-method is `KSEM299`.

Several declarations may share a name when their parameter lists differ.
Type-parameterized functions are instantiated at a call. Arguments are inferred
from values, or supplied explicitly as `identity<Int>(7)`; an unresolved
specialization is `KSEM316`.

## `let`

```kira
let answer = 6 * 7
let greeting: String = "hello " + audience()
let table = buildTable()
```

A module-scope constant: one value per program, computed once at program start — before `@Main` runs — and shared by every reader. The initializer is an ordinary runtime expression; function calls are allowed, so a parsed table or a decoded resource is built once instead of per use. A read copies with value semantics, exactly as a local read does.

Each constant is evaluated after every constant it depends on, whatever order the declarations were written in and whichever files they sit in. Dependencies are computed from resolved references, transitively through every function the initializer can call — including a field default a construction fills — so two unrelated declarations that merely share a method name never depend on each other. An initializer that reaches its own value, directly or through the call graph, is a dependency cycle: `KSEM317`. A missing `=` initializer is `KPAR034`.

Constants share the value namespace with top-level functions: a constant colliding with a function or another constant is `KSEM316`. A local of the same name shadows a constant inside a body. There is no module-scope `var`, and a value whose type runs a user `Drop` cannot be a constant (`KSEM318`) — it would need one owner, and a constant has every reader.

## `struct`

```kira
struct Name {
    let member: T
    var other: U = default
    function method(borrow self) -> R { … }
}
```

Members may be `let` or `var` and may carry a default. Field type order does not matter; a by-value cycle is `KSEM052`. A struct is constructed by a literal (`Name { field = value }`) or by its memberwise constructor (`Name(value)`, `Name(field: value)`).
`struct Name<Value> { … }` is a generic template; `Name<Int>` is the concrete
type used by a constructor or annotation.

## `class`

```kira
class Child: Trait extends Parent, Other {
    override let member = newDefault
    function method() -> R { … }
}

class BoxChild<Value> extends Box<Value> {
    function read(borrow self) -> Value { return self.value }
}
```

`:` is conformance and `extends` is a parent, traits first. `extends` takes a
comma-separated list and may name a `struct` or a concrete generic aggregate
such as `Box<Value>`. A generic child substitutes its parameters into the
parent before flattening fields and methods. Two parents declaring one name
keeps both, so the bare name is `KSEM067` for a method and `KSEM068` for a field.

A class is built by calling it. A child value is assignable to any of its
parents, and the flattened parent fields and methods remain available on the
child.
Classes may also be generic, such as `class Box<Value> { … }`; each concrete
`Box<Type>` is a separate flattened class row.

## `enum`

```kira
enum Color: Renderable { Red Green Blue }

enum Message {
    Empty
    Text(String)
    InvalidFormat: String = "not that format"
}

enum Result<Value, Failure> {
    Ok(Value)
    Error(Failure)
}
```

Variants are separated by newlines or spaces, never commas. A variant carries at most one payload, written `(T)` or `: T`, optionally with `= default`. A payload may be `Int`, `Float`, `Bool`, `String`, an array, a struct, another enum, or `Any`; `Void`, `CString`, `RawPtr`, and runtime handles are `KSEM118`.

An enum may claim traits after its optional type parameters, just like a struct or class. Any concrete type can also be the target of an `extend` impl, including a scalar, string, array, or alias that resolves to one:

```kira
extend Int: Renderable {
    function render(borrow self) -> String { return "integer" }
}

extend [Int]: Renderable {
    function render(borrow self) -> String { return "array" }
}
```

The conformance table uses the resolved type identity, not a declaration kind, so fixed-width scalar spellings remain distinct and aliases do not create duplicate types. A generic declaration may also carry a conformance; each monomorphized instantiation keeps its own resolved identity.

Enums, structs, classes, traits, and functions may take type parameters. A
generic declaration is instantiated only when a complete argument list is
available; an arity mismatch is `KSEM174`, while a type argument on a
non-generic declaration is `KSEM173`.

## `trait`

```kira
trait Ordered: Equated {
    function less(borrow self, other: Int) -> Bool
    function atMost(borrow self, other: Int) -> Bool { … }
}
```

A bodyless member is a requirement; one with a body is a default. A trait with no members is a marker. A `:` clause on a trait names supertraits. Traits may be generic (`trait Provider<Value> { … }`), and `Provider<Int>` is the concrete contract named by a conformance or bound. Declaring `Copyable`, `Drop`, `Send`, or `Sync` is `KSEM288`.

## `construct`

```kira
construct Family extends Parent { … }        // a template: no parameter list
construct Name(params) extends Family { … }  // a declaration
```

The parameter list tells the two apart. A parameter list with no `extends` is `KPAR077`; a declaration naming two families is `KPAR078`. See [Constructs Reference](/docs/language-reference/constructs-reference).

## `extend`

```kira
extend Type: Trait { … }     // a trait impl block
extend Family { … }          // fluent modifiers on a construct family
```

The colon form implements exactly one trait for one type and may carry only members that trait declares (`KSEM294`). Writing a conformance both in a declaration's colon list and in an `extend` block is `KSEM290`. A conformance may be declared only in the package that declares the type or the package that declares the trait (`KSEM291`).

The colon-free form adds family-level methods whose receiver is the family value.

## `type`

```kira
type Count = Int
type Buffer = [Count]
```

A spelling, not a new type. A cyclic chain is `KSEM157`; claiming a taken name is `KSEM130`.

## `distinct`

```kira
distinct TabId = U32
distinct BookmarkId = U32
```

A new type over one scalar word, and the opposite of `type`. `TabId(value)` builds one and `id.raw` reads the representation back; nothing else crosses, in either direction, and `BookmarkId` is a third type rather than the same one.

The representation is an integer width, a float width, `Bool`, `RawPtr`, or another distinct type; anything else is `KSEM345`. A cyclic chain is `KSEM346`; claiming a taken name is `KSEM130`. The declaration takes no annotation (`KPAR087`), and `@Derive(Copy)` on one is `KPAR086` — a scalar word is copyable already.

See [Distinct Types](/docs/language-reference/types#distinct-types) for the layout guarantee, the operator surface, the C seam, and which derives apply.

## Macros

```kira
macro Name(p: expr) { expand { … } }
comptime macro Name { kind { … } expand(…) -> Syntax { … } }
comptime function name(p: Int) -> Int { … }
```

See [Macros](/docs/macros).

## Package Manifests

`package.kira` is a declaration too, in the same language, and is read by the package layer rather than by the program.

```kira
Package greetings {
    let version = "0.1.0"
    let kind = .Library
    let moduleRoot = "Greetings"
}
```

See [Libraries and Packages](/docs/appendix/cli/packages).
