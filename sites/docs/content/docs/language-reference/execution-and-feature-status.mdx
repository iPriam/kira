`Yes` means the engine executes the surface and a checked-in test proves it. A refusal is written as the diagnostic that fires.

Macro expansion is a frontend pass, so macro parity is structural: by the time a backend sees an expansion it is ordinary Kira. There is no per-backend macro work. The same holds for imports, generics, closures, construct families, and trait existentials, all of which are resolved above the IR.

The Web column is the same LLVM lowering the host runs, through emscripten. `crates/kira-cli/tests/end_to_end/web.rs` builds a module and compares its output against the VM's under node, so a layout mistake shows up as a wrong value rather than hiding.

## Interop

| Surface | VM | LLVM | Hybrid |
| --- | --- | --- | --- |
| `@FFI.Extern` scalar and `RawPtr` signatures | Yes | Yes | Yes |
| `CString` parameters and results | Yes | Yes | Yes |
| `@FFI.Struct` by value and by address | Yes | Yes | Yes |
| `@FFI.Array` members and pointer-backed storage | Yes | Yes | Yes |
| `@FFI.Callback` values, including Kira functions as C callbacks | Yes | Yes | Yes |
| Member reads through an `@FFI.Pointer` | Yes | Yes | Yes |
| Generated bindings from headers (`autobind`) | Yes | Yes | Yes |
| `@FFI.Syscall` | Host-served; seven calls refused | Yes | Yes |
| Library `@Export` and the generated Rust crate | Yes | Yes | Yes |

No `@Native` is required to call C on any engine. The VM asks its host, which answers out of a generated adapter sidecar.

On the Web target a build passes the matching `wasm32-emscripten` archive and the generated adapters to `emcc`. Every supported scalar and `RawPtr` type works, and `CString` works in both directions; a C pointer is four bytes there, so a C-layout struct's member offsets are computed per target rather than reused from the host. Scalar and `CString` callbacks are direct LLVM functions. A callback with a by-value aggregate parameter gets a generated C entry so emscripten, not Kira's LLVM lowering, classifies that parameter before forwarding its address to the callback body. `@FFI.Syscall` has no kernel to reach and is refused. The VM engine's generated Rust crate builds for `wasm32-unknown-unknown`; the hybrid engine's does not, because it needs a dynamic loader.

`@FFI.Syscall` emits an instruction, which an interpreter has none of, so the VM asks its host instead. `read`, `write`, and `ppoll` are served because they take a descriptor the program already holds; the other seven are refused by name before the program starts. A non-Linux target is `KSEM280`, and Linux on a processor with no entry sequence is `KSEM281`.

## Shaders

`.ksl` is a separate language with its own lexer, parser, semantics, and typed shader IR. It is compiled by `kira shader build` and by the `Ksl.compile` compile-time call a `comptime macro` reaches.

| Target | `--target` | Emits |
| --- | --- | --- |
| GLSL 430 | `glsl_430`, `glsl` | Vertex, fragment, and compute source |
| WGSL | `wgsl` | Vertex, fragment, and compute source |
| HLSL | `hlsl` | Vertex, fragment, and compute source |
| MSL | `msl`, `metal` | One combined module holding every stage |
| SPIR-V | `spirv`, `spv` | A binary word stream, one module per stage |

**Compute shaders are emitted by every target.** GLSL declares a `local_size_x/y/z` layout, HLSL a `[numthreads(…)]` attribute, MSL a `kernel` entry, and SPIR-V a `GLCompute` execution model.

The one shape a target cannot express is a SPIR-V compute entry point that declares output variables: SPIR-V has none there, and a compute shader publishes through storage. That leaves the SPIR-V source empty and reports a note, because the other four targets still carry the shader.

`Ksl.compile` answers with every member as a `String`, so SPIR-V arrives as hexadecimal with eight characters to a word, ready to read into the `uint32_t` array `vkCreateShaderModule` takes.

## Platforms

| Target | State |
| --- | --- |
| Host desktop (macOS, Linux, Windows) | `run`, `build`, `test`, `debug`, `profile`, `live` |
| Cross targets (`--target arch-os-abi`) | `build` and `check`. `run`, `test`, and `debug` refuse a cross target by name. |
| Web (`--device wasm32`) | `build`, `export web`, and `live web`. A built module runs headlessly under node. |
| Apple (macOS, iOS, tvOS, visionOS) | `export apple` writes a real Xcode workspace; `live` runs the app it builds. |
| Windows, Linux | `export` writes a CMake or Visual Studio scaffold and audits the tools a local build needs. |
| Android | Modeled. `export` and `live` refuse by name rather than emitting a project no build produced. |

## What Is Still Refused

| Shape | Answer |
| --- | --- |
| A returned borrow | Refused rather than accepted with incomplete lifetime checking. |
| Field-sensitive partial moves | A struct moves whole. |
| A `Drop` value read out of a member, an element, or a payload | `KSEM302`. Bind the owner. |
| Generic declaration members with their own type parameters | `KPAR047`. Type parameters belong on the enclosing function or aggregate declaration. |
| Subtyping between classes | `KSEM063`. Use a trait or a construct family. |
| `print` of a struct, array, or enum | `KSEM081`. No rendering is pinned anywhere. |
| Payload-carrying enums as direct C values | Refused with a typed diagnostic. Payload-less enums cross as C integers. |
| Aggregate callback results, non-C ABIs, variadics, generic externs | Refused with a typed diagnostic. |
