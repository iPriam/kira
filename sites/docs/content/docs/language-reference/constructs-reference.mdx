`construct` declares either a family template or a declaration backed by one, told apart by the parameter list. See the [Constructs guide](/docs/language-guide/constructs) for the narrative.

## Headers

```kira
construct Family { … }
construct Family extends ParentA, ParentB { … }
construct Family: Trait { … }
construct Name(param: T, other: U = default) extends Family { … }
```

A parameter list with no `extends` is `KPAR077`. A declaration naming two families is `KPAR078`. A parent that is not a family is `KSEM200`, and an inheritance cycle is `KSEM205`.

## Members

| Written | Kind |
| --- | --- |
| `let name: T` | Immutable stored member. |
| `var name: T` | Mutable stored member. |
| `let name: T = default` | Stored member with a default. |
| `let name: T { expr }` | Computed member: a zero-argument method read as a property. |
| `name { … }` | Shorthand for the computed member the family declares under `name`. |
| `function f(…) -> T { … }` | An inheritable default. |
| `@Required function f(…) -> T` | A bodyless requirement. |
| `requires { function f(…) -> T }` | The section spelling of the line above. |
| `@Required let name: T` | A value obligation. |
| `let name: some X` | A single child slot. `@Content let` is the same. |
| `let name: [some X]` | A list child slot. |
| `init(params) { … }` | A secondary construction path. Writes no result type (`KPAR067`). |
| `lifecycle { name(…) { … } }` | The methods a runtime holding this value calls. |

A computed member must declare its result type (`KPAR066`). A declaration that leaves a requirement unimplemented is `KSEM234`.

**The result type comes from the family.** A `name { … }` shorthand returns whatever the family declares for `name`; a family that declares no such member falls back to the family type.

## Values

| Written | Means |
| --- | --- |
| `Family` | Refused (`KSEM207`). |
| `Any Family` | A value of some declaration backing `Family`. |
| `some Family` | The same type. In a member position it also marks a child slot. |
| `[Any Family]` | A heterogeneous array of them. |

## Narrowing

A child may make a promise more specific, never different. A result and a `@Required let` may narrow: anything narrows `Any`, and a family type narrows to a family extending it or to a declaration backing one. A parameter may not. Either violation is `KSEM206`.

## Content Blocks

A trailing `{ … }` fills the **last** content parameter of a construction, an `init`, or a method. Its items are bare child expressions plus two builders recognized only there:

```kira
For(binding in iterable) { … }
if condition { … } else if other { … } else { … }
```

A `For` builder contributes one child per iteration; an `if` builder contributes the taken branch's children. A `For` with no `{` is `KPAR065`.

A `{ … }` is read as a content block only when it is neither a closure (it has an `in`) nor a struct literal (its first item is `name =` or `name :`) nor a copy/update (its items are `let` overrides).

## Copy and Update

```kira
let wide = base { let width = 200 }
```

The local is evaluated once, its fields are copied into a new construction, and only the written paths are replaced.

## Modifiers

```kira
extend Family {
    function padding(amount: Int) -> Any Family { … }
}
```

One shared body whose receiver is the family value, returning the family type. A modifier whose name is already taken by the family is refused rather than shadowing it. Only `function` members are legal in the block.

## Traits on a Family

`construct Family: Trait { … }` and `extend Family: Trait { … }` both file one conformance per backed declaration. A compiler-known trait cannot be claimed by a family (`KSEM298`).

## Lowering

A family becomes a synthesized enum whose variants carry the backed structs. A method call through a family value becomes a tag dispatcher; a `@Required let` read becomes a per-variant dispatcher whose arms differ; a modifier becomes one function taking the family value as its receiver. A `borrow mut self` requirement carries the updated selected payload back through the dispatcher to the caller's mutable place. Every backend runs ordinary enum projection, branching, and direct calls, so constructs introduce no IR node, no opcode, and no wire format.
