This manual describes the toolchain in this checkout. Ask the installed one what it is:

```bash
kira --version
knvm list
```

## Version Numbers

A released version may carry a fourth component: `1.8.3.1`. Cargo cannot express one, so `[workspace.package] version` carries the three-component prefix and the release job passes the whole string through `KIRA_RELEASE_VERSION`. A development build reports the Cargo version.

Channels are independent installs. `release` is a GitHub release not marked prerelease, `dev` is the prerelease feed. `latest` resolves inside one channel and never across them.

## What Is Stable

| Surface | Stability |
| --- | --- |
| Diagnostic codes | Stable. A code names one refusal and is not reused. |
| `KBC1` bytecode, `KHM1` hybrid manifest, `KLB1` bundle manifest | Versioned wire formats. A decoder rejects a tag it does not know. |
| `kira_lib_<library>_<export>` trampoline names | A fixed contract the generated Rust crate reads. |
| Generated derive function names (`eq_Point`, `serialize_Point`) | A fixed contract other tooling reads. |
| Language syntax | Moving. A migration that makes the language cleaner is preferred to compatibility with a shape that was wrong. |

## Pinning a Project

`knvm pin <version>` writes a `kira-toolchain.toml` in the working directory, and the launcher walks up from its working directory so the nearest pin wins over the global selection. See [Selecting a Toolchain](/docs/appendix/toolchains/selecting).
