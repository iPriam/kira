function projectedRunway(quarters: Int) -> Int {

Parameters require explicit types. A result type is written after `->`, or after `:` when the result is itself a function type, because `->` would be ambiguous with the function type's own arrow. A body is a block, except for an `@FFI.Extern` or `@FFI.Syscall` declaration, which has none and ends with its signature.

## Parameter Defaults

A parameter may declare a default with `=`, and a call may then omit its argument.

```kira
function step(base: Int, by: Int = 1, tag: Int = 100) -> Int {
    return base + by + tag
}

print(step(1))               // 102, both defaults filled
print(step(1, 5))            // 106, one default filled
print(step(base: 1, tag: 9)) // 11, a labeled call omits the middle default
```

A positional call fills omitted **trailing** arguments; a labeled call may omit any defaulted parameter, middle ones included. Every call path fills the same way: a free function, a method, and a construct-family modifier alike. A parameter with no default is still mandatory, and omitting it is `KSEM062`.

The default's **expression** is resolved once, in the file the function was declared in, so it may name that file's helpers regardless of where the call is written. That resolved expression is then **evaluated on every call** that omits the argument, exactly as writing the argument out at each call site would be: a default that calls a function calls it once per call, not once per program. Two defaults that fill each other through the call graph have no finite value and are refused with `KSEM240`.

## Generic Functions

A function may declare type parameters and use them in its parameter and result
types:

```kira
function identity<Value>(value: Value) -> Value { return value }

let number = identity(7)       // inferred as Int
let text = identity<String>("ok")
```

The compiler infers each parameter from the corresponding value argument. Write
`name<Type>(…)` when inference has no answer or when an explicit specialization
is clearer. Every concrete specialization is checked and emitted like an
ordinary function; an ambiguous or incomplete inference is `KSEM316`, and a
wrong number of type arguments is `KSEM174`.

## Ownership at the Call Site

A plain parameter consumes the value it is given, so passing a *named* non-trivial value to one must write `move`.

```kira
function consume(v: Vec3) -> Int { return v.x + v.y + v.z }
function sum(v: borrow Vec3) -> Int { return v.x + v.y + v.z }

print(sum(v))            // a borrow reads and gives back; `v` survives
print(consume(move v))   // this takes `v` away
print(v.x)               // KSEM107: `v` was moved
```

There are five modes: `owned` (the default), `borrow`, `borrow mut`, `move`, and `copy`. [Memory and Safety](/docs/language-guide/memory-and-safety) covers what each one costs and which values need a spelling.

## Closures

A closure is a function value, written `{ params in body }`; its type is written `(A, B) -> R`. A closure never annotates its parameters, so a literal only makes sense where a function type is already expected: an annotation, an argument, a field, or a `return`. Nowhere else says what the parameters are, and guessing is refused (`KSEM134`) rather than attempted.

```kira
function apply(f: borrow (Int) -> Int, x: Int) -> Int { return f(x) }

function makeAdder(step: Int): (Int) -> Int {     // a result type after `:`
    return { value in return value + step }
}

let scale: (Int) -> Int = { v in return v * 2 }   // one parameter
let pick: (Int, Int) -> Int = { a, b in return a }
let now: () -> Int = { in return 1 }              // zero parameters: a bare `in`

each { value in print(value) }                    // trailing: the last argument
runWithConfig(2) { frame in draw(frame) }         // after the other arguments
```

A top-level function name is a function value too. An expected function type checks its parameter and result types exactly; without an expectation, the function's signature supplies the type. A mismatch is `KSEM212`.

**A closure costs no opcode, no IR node, and no backend code.** A function type becomes a synthesized struct, a tag plus the captures of every literal of that type; a literal becomes a lifted top-level function plus a value of that struct; and a call through a closure value becomes a call to a synthesized dispatcher that branches on the tag. Every construct that reaches the IR is one every backend already ran.

### Capture

**A `let` is captured by value; a `var` is shared.** Which applies is decided by how the binding was declared.

- A `let` of `Int`, `Float`, or `Bool` is copied into the closure when it is built. A `let` of `String`, struct, array, or enum is refused (`KSEM117`): those own heap storage, and only the scalars copy for free.
- A `var` a closure mentions moves into a **capture cell** at its declaration, a share-counted heap box, and the closure holds a share of it. A write through either side is visible through the other, and the box outlives the frame that declared it, so a closure that escapes keeps working.

```kira
function makeCounter(): () -> Int {
    var seen = 0
    return { in
        seen = seen + 1
        return seen
    }
}
```

A `var` with no storage of its own has no shared form and is still refused (`KSEM117`): a `borrow mut` parameter names the caller's storage, and a recovered callback-state view is a window into a host's.

A cell never crosses the C seam, the hybrid seam, or into `Any`, because a hold taken outside this runtime is a hold nothing releases. A cell holding a closure that captures the same cell is a cycle share counts cannot collect: it leaks, memory-safely and permanently.

Captures nest and shadow the way bindings do. A closure two deep captures an outer binding *through* the closure between it rather than reaching past it, a parameter shadows a capture of the same name, and a name is readable as a capture before an inner `let` of that name rebinds it.

A closure lifted out of a method has no `self`, so a bare field name in its body is an undefined name rather than a silent capture.

## Floating-Point Primitives

These are free functions the compiler answers directly. Every one takes `Float` operands and answers a `Float`.

| Group | Names |
| --- | --- |
| Roots and powers | `sqrt`, `pow`, `hypot` |
| Exponential | `exp`, `exp2` |
| Logarithmic | `log`, `log2`, `log10` |
| Trigonometric | `sin`, `cos`, `tan`, `asin`, `acos`, `atan`, `atan2` |
| Hyperbolic | `sinh`, `cosh`, `tanh` |
| Rounding | `floor`, `ceil`, `round`, `trunc` |
| Selection and sign | `min`, `max`, `abs`, `copysign` |
| Remainder | `fmod` |

```kira
let hypotenuse = sqrt(a * a + b * b)
let wave = sin(phase) * amplitude
let encoded = 1.055 * pow(channel, 1.0 / 2.4) - 0.055   // an sRGB transfer curve
let angle = atan2(dy, dx)
```

`round` takes halves away from zero, `trunc` drops the fraction toward zero, and `fmod` is what `%` means on floats, with the remainder truncated toward zero, so its sign follows the dividend.

They are primitives rather than library code because every target already has them, as an `sqrtsd` on x86, an LLVM intrinsic, or a libm call, and a language whose users reach a square root through eight Newton iterations has an approximation where it should have an answer. `sqrt(2.0)` is exact to the last bit. The operations use the platform's full-precision math implementation on every backend.

They travel as one `MathOp` instruction told apart by an operand byte, so a new operation costs a number in that table and nothing in the opcode table.

A program may still define its own `sqrt`: the primitive answers only when nothing else does.

## Overloading

Several declarations may answer to one name when their parameter lists differ, by type or by arity. It works for free functions, for struct, class, and construct-backed methods, and a subclass may override one overload and inherit the rest.

Two rules pick among them at a call:

- **Specificity.** An argument that *is* the parameter's type beats one erased into it, so a concrete declaration wins over an `Any Family` parameter.
- **Directness.** An exact arity beats one that leans on a parameter default.
