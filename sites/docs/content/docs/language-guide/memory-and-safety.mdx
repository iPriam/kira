Kira owns by default, and says so at the call site.

```kira
function consume(v: Vec3) -> Int { return v.x + v.y + v.z }
function sum(v: borrow Vec3) -> Int { return v.x + v.y + v.z }

let v = Vec3 { x = 1, y = 2, z = 3 }
print(sum(v))            // a borrow reads and gives back; `v` survives
print(consume(move v))   // this takes `v` away
print(v.x)               // KSEM107: `v` was moved and is no longer available
```

## The Five Modes

| Mode | Written | Meaning |
| --- | --- | --- |
| owned | nothing | The parameter consumes the value it is given. |
| `borrow` | on the parameter | A shared read. The caller goes on holding the value. |
| `borrow mut` | on the parameter | Exclusive mutation, written back through the caller's binding. |
| `move` | at the call site | Hands a named value over. |
| `copy` | at the call site, or as a parameter mode | An explicit non-consuming value copy. |

All four written spellings are **contextual identifiers**, not reserved keywords: a variable named `move` still parses, because a `move` is only an operator when an operand follows it.

## Which Values Need a Spelling

One predicate decides it: **trivially copyable** covers `Void`, `Int`, `Float`, and `Bool`. A `String` is not trivially copyable, because it owns its bytes, and neither is a struct, so both need `move` or `copy` into a consuming parameter. A temporary never does: `consume(Vec3 { … })` binds nothing, so there is nothing to lose track of.

A struct nonetheless **copies when bound**: `var w = v` deep-copies and `v` stays live. Needing a spelling and moving on bind are different questions, and a struct answers them differently. An **array** and an **enum** are the types that answer the second one yes: their bindings alias where a struct copies, so binding one moves it.

`copy` copies scalars by their bits, strings and structs by their owned storage, and arrays through copy-on-write. It lowers on every engine; what it requires is the *spelling*, so the ownership checker can tell an intended copy from an intended move. Passing a named non-trivial value to a copying parameter with neither word written is `KSEM113`, and writing `move` where the parameter copies is `KSEM115`.

## What Each Mode Costs a Backend

**`borrow mut` writes through the caller's binding.** It is the one mode observable at run time, so it is the one mode a backend carries: the parameter is passed by reference, and the call site records where the callee's final value lands.

```kira
function bump(c: borrow mut Counter, by: Int) {
    c.n = c.n + by
    return
}

var counter = Counter { n = 1 }
bump(counter, 4)
print(counter.n)          // 5, the callee wrote through
```

The argument has to name storage, not a temporary (`KSEM248`), and one call may not mutably borrow the same binding twice (`KSEM247`): both writes would land in one place and the later would erase the earlier.

**The other four modes cost a backend nothing.** For today's types a `move` and a `borrow` are both indistinguishable from the deep copy the runtime already performs, because a caller that moved a value can never look at it again until it assigns the binding a new one, which is exactly what the checker guarantees. They are a static check.

## Drop

A type claims `Drop` and implements its one member.

```kira
struct Handle: Drop {
    let raw: Int
    function drop(borrow mut self) { closeHandle(raw) }
}
```

The body runs **once, before the type's own members are released**, at every point either engine releases a value of the type: a binding going out of its lexical block, a loop iteration ending, a container being freed, a value moved into a callee dying there rather than at the binding it was moved out of, and a write replacing what a binding, a member, or an element held. A value declared in a nested block is released before execution resumes after that block; a `break` or `continue` releases bindings in the loop body before it jumps.

The guarantee is that **every `Drop` body runs before the run that made the value ends.** Nothing can enter a body where no engine is executing, so a type that runs one is refused at each position that would outlive the run.

Two rules follow, and neither is optional.

- **The body is never called by name.** `value.drop()` is `KSEM300`. A release is the compiler's to schedule, and a hand-written call would run the body a second time and leave the value looking alive.
- **The type moves rather than copies.** A copy would be a second value with the same body to run, so a `Copyable` claim on a `Drop` type is `KSEM297`, and so is one on a type that merely *holds* a `Drop` value.

`drop` takes no arguments and returns nothing; anything else is `KSEM301`.

### One Owner

A value that runs a body has one owner and no copy. Reading one out of the value that holds it would make a second value with the same body to run, so a read is legal only where it does not take.

| Written | Answer |
| --- | --- |
| `pair.first.tag`, `bag.items.count`, `bag.items[0].tag` | Legal. The read walks to the value's own storage. |
| `read(pair.first)` where `read` borrows | Legal. The caller goes on holding the value. |
| `pair.first.value()` on a non-mutating method | Legal. The receiver is borrowed. |
| `let stolen = pair.first`, `let taken = arr[1]` | `KSEM302`. The binding is a second owner. |
| `pair.first.bump()` on a mutating method | `KSEM302`. A mutating receiver is taken by value. |
| `for item in items` over `Drop` elements | `KSEM302`. The cursor binds one element per iteration. |
| `make().held.tag` | `KSEM302`. A temporary is released at the end of the statement. |
| A closure capturing one | `KSEM302`. A captured `var` is shared with the scope that declared it. |

Bind the owner and read through it, or move the whole owner.

### Refused Positions

Each position below outlives the run that made the value, or copies it.

| Position | Code |
| --- | --- |
| An `@Export` parameter or result | `KSEM303` |
| `nativeState` and `nativeRecover` | `KSEM304` |
| A `retains:` foreign parameter | `KSEM305` |
| An enum variant payload, including a generic instantiation and a construct-backed declaration | `KSEM306` |
| A parameter or result of an `@Native` or `@Runtime` function | `KSEM307` |

A `Drop` body itself declares no engine (`KSEM301` if it does): a release happens wherever the value dies, so the body is compiled into both halves of a hybrid build and runs the same source on either one. A value may be built, used, and released inside one half; what may not happen is the crossing, which marshals a copy.

### Teardown

A parked release outside any frame gives its storage back rather than running the body. `Instance::release`, `Instance::release_all`, and `Instance::finish` hold no engine to enter a body with, so a value that reached one is abandoned. Nothing an author can write reaches that path: the refusals above are what make the guarantee hold, and this is what keeps a module built by other means from leaking.

## Capture Cells

A `var` a closure mentions moves into a share-counted heap box that outlives the frame that declared it. A cell never crosses the C seam, the hybrid seam, or into `Any`, because a hold taken outside this runtime is a hold nothing releases. A cell holding a closure that captures the same cell is a cycle share counts cannot collect: it leaks, memory-safely and permanently. See [Functions](/docs/language-guide/functions#capture).

## No GC, No ARC

Nothing in the core runtime hot path reference-counts an ordinary value. A struct copies, an array detaches on write, and a `String` owns its bytes. Share counting exists in exactly two places: a capture cell, and an array's element block under copy-on-write.

## What Is Still Refused

- A returned borrow is refused rather than accepted with incomplete lifetime checking.
- Field-sensitive partial moves are not complete: a struct moves whole.
- A `Drop` value cannot be moved out of a member, an element, or an enum payload; the owner moves whole.
- LLVM ownership ABI annotations such as broad `readonly` and `noalias` use are not applied everywhere the checker's facts would allow.
