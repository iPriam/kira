A construct family is a typed template. It states what every declaration backed by it must provide, and each backed declaration is an ordinary struct that provides it.

```kira
construct Widget {
    @Required function render() -> String
    function announce() -> String { return "<" + render() + ">" }
}

construct Text(content: String) extends Widget {
    render { return content }
}

construct Divider() extends Widget {
    render { return "---" }
}
```

**The parameter list tells the two apart.** A `construct` with one is a declaration: the parameters are its construction inputs, and `extends` names the one family backing it. A `construct` without one is the family template, and `extends` names the families it takes requirements and members from. A parameter list with no `extends` is `KPAR077`, and a declaration naming two families is `KPAR078`.

`@Required` states an obligation; a member with a body is inherited by every declaration that does not write its own. A declaration that leaves a requirement unimplemented is `KSEM234`.

## A Family Is Not a Type

A family is not one of its own values, so naming the type takes `Any Widget` or `some Widget`. Both say "a value of some declaration backing `Widget`", and they resolve to the same type. The bare name is `KSEM207`: left accepted it reads like a concrete type and hides that the value is heterogeneous.

```kira
let items: [Any Widget] = [Text(content: "hi"), Divider()]
for item in items { print(item.announce()) }
```

A family becomes a synthesized enum whose variants carry the backed structs, and a call through a family value becomes a tag dispatcher. Every backend runs ordinary enum projection, branching, and direct calls, so nothing here is a backend feature. A method requirement written with `borrow mut self` dispatches through the same tree while rebuilding the selected payload and writing the updated family value back to the caller's `var` binding.

## Members

| Written | What it is |
| --- | --- |
| `let name: T` | An immutable stored member. On a declaration it is a field. |
| `var name: T` | A mutable stored member. A mutating method may write through it. |
| `let name: T = default` | The same, with a default filling every construction that omits it. |
| `let name: T { expr }` | A computed member: a zero-argument method read as a property. |
| `name { … }` | The shorthand for a computed member whose result type the family declares for `name`. |
| `function f(…) -> T { … }` | A default the family provides to every declaration that writes no own. |
| `@Required function f(…) -> T` | A bodyless signature every backed declaration must implement. |
| `requires { function f(…) -> T }` | The section spelling of the line above. A family may mix the two. |
| `@Required let name: T` | A value obligation. A declaration discharges it with a stored field or a computed member. |
| `let name: some X` / `let name: [some X]` | A child slot, filled by a construction's trailing block. `@Content let` is the same thing. |
| `init(params) { … }` | Another way of constructing the declaration. |
| `lifecycle { onAppear() { … } }` | The methods a runtime holding this value is meant to call. |

A `@Required function` is bodyless by definition: a requirement carrying a body would be an inheritable default, which is the plain `function` member instead (`KPAR065`).

### The Shorthand

```kira
construct SumsToTen() extends Test {
    test { return add(4, 6) }
    expect { let e: Result<Int, TestFailure> = .Ok(10) return e }
}
```

**The result type comes from the family, not from the shorthand.** A `name { … }` member is the body of the member the family calls `name`, so what it returns is the family's to state. A family that declares no such member falls back to the family type, which is what keeps a `body { … }` on a family that never mentions `body` meaning what it always did. No name is special-cased.

### Initializers

The parenthesized header fills the stored members. Each `init` is another way, told apart by what it takes, whose body ends in a construction through the header.

```kira
construct Link(destination: Any Widget, label: Any Widget) extends Widget {
    init(title: String, value: Int) {
        return Link(destination: Leaf(number: value), label: Text(text: title))
    }

    init(value: Int, label: some Widget) {
        return Link(destination: Leaf(number: value), label: label)
    }
}
```

An `init` writes no result type: there is only one thing it can produce, and restating it would be the declaration's name twice on one line (`KPAR067`).

## `extends`

A family may extend others. It takes on their requirements and members, and every declaration backed by it also becomes a value of each parent's type.

```kira
construct Runnable {
    @Required function label() -> String
    function announce() -> String { return "run " + label() }
}

construct Task extends Runnable {}

construct Fetch() extends Task { label { return "fetch" } }

function drive(items: borrow [Any Runnable]) {
    for item in items { print(item.announce()) }
}
```

`drive` never names `Task`. That is what the clause buys: a runtime holds `[Any Runnable]`, keeps instances, and drives declarations written against families it has never heard of.

Inheritance is transitive, a cycle is `KSEM205`, and a parent that is not a family is `KSEM200`.

**A child may make a promise more specific, never different.** A result and a `@Required let` member may narrow: anything narrows `Any`, and a family type narrows to a family extending it or to a declaration backing one. A *parameter* may not, because everything holding an `Any Runnable` passes whatever the parent's signature accepts, and a child asking for less would refuse a value the parent promised to take. Either way it is `KSEM206`.

```kira
construct Parent {
    @Required function render() -> Any
    @Required function accept(value: Any) -> Bool
}

construct Child extends Parent {
    @Required function render() -> String             // narrows a result: allowed
    @Required function accept(value: String) -> Bool  // KSEM206
}
```

A dispatcher carries a narrowed answer up to the result the family it belongs to declared, so reading `render()` through `Any Parent` yields the erased `Any` and reading it through `Any Child` yields the `String`.

## Content Slots

A member whose type is written `some X` or `[some X]` is a **child slot**: it is filled by the trailing `{ … }` block on a construction rather than by a parenthesized argument.

```kira
construct Row(gap: Int = 0) extends Widget {
    let children: [some Widget]

    function total() -> Int {
        var sum = gap
        for child in children { sum = sum + child.total() }
        return sum
    }
}

Row(gap: 8) {
    Text(content: "left")
    Text(content: "right")
}
```

The children fill the **last** slot, because they are written after every parenthesized argument. That rule applies wherever such a parameter is declared, so a **method** takes a trailing block too, and a modifier no longer has to name a container its caller does not care about:

```kira
let node = Leaf(n: 3).paired {
    Leaf(n: 4)
}
```

When the block is the whole argument list, the parentheses go away entirely.

### Builders

Inside a content block, `For` and `if` produce children by control flow. They are recognized only there, so a `For(…)` or an `if` anywhere else parses as it always did.

```kira
Row(gap: 0) {
    For(part in parts) {
        Leaf(n: part)
    }
    if wide {
        Divider()
    } else {
        Text(content: "narrow")
    }
}
```

## Copy and Update

A braced name that resolves to an existing construct value evaluates it once, copies its fields, and replaces only the paths written.

```kira
let wide = base { let width = 200 }
```

The result uses the same nodes an ordinary construction does, so no backend needs an update operation.

## Fluent Modifiers

`extend Family { … }` adds modifiers to a family. A modifier is a family-level method with one shared body whose receiver is the family value, distinct from the per-variant methods a `construct` family declares. It returns the family type and wraps `self`, which is what makes `text.padding(8).background(fill)` chain.

```kira
extend Widget {
    function padding(amount: Int) -> Any Widget {
        return Padding(amount: amount) { self }
    }
}
```

A modifier whose name is already taken by the family is refused rather than shadowing the declared method. `extend Family { … }` with no colon is the modifier block; `extend Type: Trait { … }` with one is the [trait impl block](/docs/language-guide/traits#retroactive-conformance).

## Traits on a Family

A family may claim a trait in either spelling, `construct Widget: Hashable { … }` or `extend Widget: Hashable { … }`. A family is a template, so the claim files one conformance per backed declaration; members the family provides answer for every variant at once. A compiler-known trait cannot be claimed by a family (`KSEM298`).

## Why This Exists

The compiler provides the mechanism; the framework stays in Kira source. `Test` in `tests-kik/harness` is a construct family a package declares, and nothing in the compiler knows the name. A UI library's `Widget`, `View`, and `Route` are the same thing: one construct declaration each, with the layout and rendering written in Kira beside them.
